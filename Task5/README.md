# Интеграционные и end-to-end тесты

| Название | Тип | Компоненты | Предусловия | Действия и ожидаемый результат |
| --- | --- | --- | --- | --- |
| Успешный платёж | E2E | Оркестратор, Camunda, Payment, FraudCheck, Notification | Достаточный баланс, проверки возвращают ALLOW | Запустить платёж. Одно списание и один перевод, `SUCCEEDED`, клиент уведомлён; возврат отсутствует |
| Автоматический антифрод-отказ | E2E | Оркестратор, Camunda, Payment, FraudCheck, Notification, приёмник безопасности | Списание успешно, FraudCheck возвращает DENY | Проверить автоматический возврат на полную сумму, `REFUNDED`, отсутствие перевода, уведомления клиента и безопасности |
| Ручное разрешение | E2E | Camunda, Tasklist, оркестратор, Payment, Notification | Ответ MANUAL, дедлайн 20 минут, оператор имеет доступ к задаче | До решения нет перевода. После ALLOW оператора — один перевод и источник решения `operator` |
| Ручной запрет | E2E | Camunda, Tasklist, оркестратор, Payment, Notification, безопасность | Ответ MANUAL, средства списаны | После DENY оператора — возврат без перевода, `REFUNDED`, уведомления клиента и безопасности |
| Cut-off автоматической проверки | E2E | Camunda, FraudCheck, оркестратор, Payment | Ответ проверки не поступает, настроен cut-off | До дедлайна деньги не переводятся. По таймеру принимается ALLOW с источником `cutoff`, выполняется перевод |
| Cut-off ручной проверки | E2E | Camunda, Tasklist, оркестратор, Payment | MANUAL, оператор не завершает задачу | Через 20 минут задача прерывается, платёж проводится. Быстрый прогон — 3 секунды; настройка основного срока — 1200 секунд |
| Ответ на границе дедлайна | Интеграционный | Camunda, FraudCheck, оркестратор | Активно ожидание с таймером, управляемая отправка сообщения | Доставить DENY одновременно с истечением срока. Побеждает один переход: если первым сработал таймер, DENY игнорируется даже до перевода; если первым принят DENY, выполняется возврат |
| Ответ внешней проверки по корреляции | Интеграционный | Camunda, FraudCheck | Два платежа ожидают `FraudDecision`, разные `payment_id` | Отправить сообщение для одного платежа. Только его ожидание завершается; второй остаётся активным. Повтор сообщения не создаёт второй денежный эффект |
| Отказ compliance или лимитов | E2E | Оркестратор, Payment, заглушки compliance и лимитов, Notification | Списание подтверждено; одна дополнительная проверка возвращает отказ | Не выполнять перевод, компенсировать списание и уведомить клиента. Причина отказа сохранена; антифрод-уведомление отправляется только при соответствующей причине |
| Невозможность списания | Интеграционный | Payment, финансовый реестр, банковская заглушка | Недостаточный баланс либо подтверждённый отказ банка | Платёж отклонён без финансового эффекта; нет проверки, перевода и возврата несуществующего списания |
| Идемпотентность денежных команд | Интеграционный | Payment, финансовый реестр, банковская заглушка | Один ключ операции, банковский ответ сохранён | Повторить списание, перевод и возврат с тем же ключом. Для каждой операции один финансовый эффект, повторы возвращают прежний результат; тот же ключ с другой суммой отклоняется |
| Подтверждённый отказ перевода | E2E | Camunda, Payment, банковская заглушка, Notification | ALLOW, списание успешно, перевод гарантированно отклонён | Pivot не достигнут. Выполнен автоматический возврат; `REFUNDED`, перевод отсутствует; уведомление безопасности не выдаётся как антифрод-событие |
| Неизвестный результат перевода | Интеграционный | Payment, банк, оркестратор | Банк принял перевод, ответ потерян | Перейти в `RESOLUTION_PENDING` и сверить результат по исходному ключу. Подтверждённый перевод завершает платёж, отказ запускает возврат; до сверки денежных команд нет |
| Повтор компенсации | E2E | Camunda, Payment, Notification | DENY, первая попытка возврата завершается временной ошибкой до эффекта | Повторить возврат. Один возврат на полную сумму, статус `REFUNDED` только после подтверждения; клиент получает конечный результат |
| Исчерпание попыток возврата | E2E | Camunda, Payment, наблюдаемость | Все попытки возврата неуспешны, списание подтверждено | Сохранить `REFUND_PENDING` и incident. После восстановления зависимости повторить компенсацию с прежним ключом |
| Сбой уведомления после pivot | E2E | Camunda, Payment, Notification | Перевод подтверждён, доставка уведомления временно недоступна | Повторить только уведомление. Денежный результат остаётся `SUCCEEDED`; возврат и повторный перевод отсутствуют |
| Перезапуск обработчика | E2E | Camunda, обработчик, Payment, финансовый реестр | Списание или возврат сохранены, подтверждение задания потеряно | Перезапустить обработчик до повторной доставки. Процесс продолжает выполнение, подтверждённая операция не дублируется |
| Перезапуск движка при ожидании | E2E | Camunda, Tasklist, оркестратор | Активна ручная проверка; данные и таймеры записаны в постоянный том | Перезапустить Zeebe. Ожидание и исходный абсолютный дедлайн сохраняются, новый срок 20 минут не отсчитывается заново |
| Отмена клиентом до pivot | E2E | Оркестратор, Payment, FraudCheck, Notification | Платёж ожидает решение после списания, перевод не начат | Зафиксировать отмену и возвратить списание. Поздний ALLOW не возобновляет перевод; конечное состояние `REFUNDED` |
| Возврат после завершения платежа | E2E | Отдельный процесс возврата, Payment, финансовый реестр, Notification | Исходный платёж `SUCCEEDED`, допустим возврат клиенту | Создать возврат с отдельным ключом. Исходная Saga остаётся завершённой; сумма и повторы контролируются |
| Согласованность конечного состояния | Интеграционный | Payment, финансовый реестр, оркестратор | Есть SUCCEEDED и REFUNDED, включая искусственно внесённое расхождение | Сверить статус и суммы: SUCCEEDED соответствует переводу, REFUNDED — подтверждённому возврату. Расхождение выявлено по `payment_id`, автоматическое изменение денежных фактов без подтверждения не выполняется |
| SLA успешных платежей | E2E, нагрузочный | Полный маршрут, наблюдаемость | Репрезентативная смесь сценариев и согласованные условия нагрузки | Измерить время от принятия платежа до подтверждённого перевода. Доля успешных операций быстрее 5 секунд не ниже 90%; доля ручных проверок и результаты по ним представлены отдельно |

## Проверки минимального прототипа

В [tests/test_process.py](../Task4.2/tests/test_process.py) выполнены 7 E2E: ALLOW, DENY, оба cut-off, отказ перевода, повторы возврата и уведомления. Оба ручных решения проверены через Tasklist.

В [tests/test_domain.py](../Task4.2/tests/test_domain.py) выполнены 6 проверок обработчиков. Банковская дедупликация, восстановление, compliance, отмена и возврат после pivot не исполняются в прототипе.
